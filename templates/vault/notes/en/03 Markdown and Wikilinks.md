# Build a thread through your notes

Notes are ordinary Markdown files. Keep a paper's interpretation in NOTES.md, cross-paper concepts in notes, and research plans in plans. Use LitThread or another editor to work with them.

## Give the idea a shape

Use headings for the question, method, evidence and uncertainty. Lists hold observations; blockquotes preserve quotations. Type / at the beginning of a line or after a space to insert headings, code, diagrams, links or Callouts. The menu stays inactive inside code blocks.

Inline math uses $E=mc^2$ and display math uses paired $$ lines. Escape literal currency dollars. Use a mermaid fenced code block for diagrams, and > [!NOTE] or > [!TIP] for Callouts.

## Link to real material

Write `[[note name]]` for a link, `[[target|label]]` for an alias, `[[note name#heading]]` for a heading anchor, and `![[target]]` for an embed. Use completion after [[ to select a real file. Include enough path to distinguish duplicate names; do not invent references to absent notes.

Place embedded images in the neighboring assets folder and use relative Markdown links. Use standard Markdown links for web sources so their origin stays inspectable.

## Preserve the working record

When another editor changes a file, compare the disk version before merging your work. Check wikilinks after moving or renaming material. Use vault-normalizer's diagnostics for larger reorganizations, preserving sources and user marks.
