# 结构与数据契约

## 代码的边界

`src/App.tsx` 组合桌面外壳。组件位于 `src/components`，业务动作和 Zustand 状态位于 `src/lib`，订阅与生命周期桥接位于 `src/hooks`。持久化、文件和进程操作通过 Tauri 命令进入 `src-tauri`，不在 React 组件中直接实现。

`crates/litthread-core` 共享目录索引、文献处理、Markdown 双链、翻译与知识库模板等能力。`cli` 使用共享 crate 提供机器接口；桌面端另行承载 Agent 会话、窗口、连接和原生交互。CLI 不启动研究 Agent。

Dockview 管理文档和拆分布局；固定研究导航负责主要入口，文件目录表达知识库结构。设置、文档和研究面板可以有独立窗口，因此公共样式和语言资源必须适用于所有入口。

## 一个知识库

```text
research-library/
├── AGENTS.md
├── papers/<topic>/<paper>/
│   ├── NOTES.md
│   ├── paper.pdf
│   ├── PAPER.md
│   ├── source/
│   ├── marks/
│   ├── assets/
│   └── attachments/
├── notes/
├── plans/
├── .agents/skills/
└── .litthread/
    ├── catalog.sqlite
    ├── config.json
    └── .trash/
```

论文标识采用知识库相对文件夹路径，不能仅使用最末级名称。`papers/` 可以有任意层级的组织目录；论文目录通过直接子项中的论文标记识别。按需建立附件目录，附件本身不构成论文身份标记。

`NOTES.md` 是用户笔记；`PAPER.md` 是可重新解析的正文；`source/` 是应保留的原始材料；`marks/*.json` 是批注和阅读相关记录。不要把用户附件放入原文目录，或直接改写 PDF 二进制来存储批注。

## 改动时保持的约束

- 路径同时兼容 Windows 分隔符、本地路径与远程知识库句柄。
- 重命名与移动经过现有双链检查和修复流程；保留链接别名、标题锚点和嵌入语法。
- 数据库迁移、JSON schema 与协议版本按数据兼容性管理，独立于应用版本。
- Agent 文件、命令与网络操作遵守现有授权边界。
- 新建模板只补充缺失文件；有版本的捆绑技能遵循显式升级规则。

第三方依赖补丁位于 `patches/`，相关包和校验由 pnpm 锁文件引用。移动原生壳位于 `src-tauri/gen`，编译生成的 Externals、assets、build 和本地签名文件不提交。

## 问题与证据工作流

证据工作台的业务模型位于 `src/lib/research/model.ts`。记录包含问题、假设、来源目录、支持/反证/背景关系、页码、用户摘录与结论。完整记录要求合法的 `papers/` 相对路径、正整数页码和非空摘录；完成度只描述填写状态，不判断研究结论正确性。

`drafts.ts` 按知识库根目录隔离窗口草稿，并验证缓存版本和数据结构。缓存保留到窗口会话结束，长期记录仍为 `notes/research/question-<uuid>.md`。保存动作位于 `actions.ts`，通过原生文件接口创建新文件，写入前再次检查知识库身份，禁止覆盖已有文件。此入口暂只支持本地桌面知识库；远程知识库的其他能力保持原契约。

AI 审查动作只准备现有 Agent 输入框，用户检查后自行发送；不自动调用模型或增加工具权限。提示词要求从原文核对页码、区分未验证摘录并寻找反证。

`src/lib/workspace/virtual-views.ts` 统一库、回收站、发现页与证据页的身份和占位数据，避免虚拟路径误入文件加载、重命名和删除流程。证据草稿页面保留在主工作区。

## 元数据与原生接口边界

`src/lib/markdown/frontmatter.ts` 是兼容入口；`frontmatter/` 分别处理文档边界、标量、属性投影与源码补丁。属性表单仅修改有变化的字段，保留未修改字段的原始引号、注释和换行；重复键、嵌套结构及不能可靠表示的 YAML 转到源码模式。

`src/lib/core/native-shell.ts` 统一窗口、应用版本、日志目录与系统打开动作；Zotero 默认目录定位位于文献导入域。依赖检查中的 `presentation-no-native-io` 禁止组件直接导入文件、路径、窗口和 opener 接口。其他原生能力按各自领域的现有契约管理。

## 版面合并的归属与诊断

`src/lib/pdf/layout/merge-captions.ts` 保留现有公共入口，`assembly/` 分离阈值、几何计算、图注亲和规则、图块、公式和执行流程。执行器先按页隔离检测框，再确定归属；同一页的检测框只能被一个结果占用。页间复用检测 ID 不互相影响。同分配对用稳定身份打破平局，公式先对候选排序再选择基线，避免输入数组顺序选择错误行。

`assembleLayout` 返回结果、来源框 ID 与归并规则，以及未纳入结果的框和排除原因；`mergeCaptionsIntoHosts` 仍只返回结果数组。图注配对先按页、类别、位置和阻隔规则生成可行候选，`matching.ts` 用整体分配优先保留最多的可行配对，再优化总亲和分；未配对的位置使用空候选，不接受不满足门槛的边。稳定 ID 排序消除检测输入顺序的影响。

原始检测框、知识库版面缓存格式和 PDF 文件保持原契约。诊断供开发与回归检查使用，不是模型正确率或研究证据验证。底层几何阈值与部分图块规则继续沿用，应与本轮新执行器区分。

画廊去重由 `layout/dedupe.ts` 处理：先检查页码、置信度、阅读顺序和框几何，再按页与类别进行抑制。候选按置信度、面积、阅读顺序及稳定身份排序，同分结果不依赖检测输入顺序；image 与 chart 共用图形类别。相交与包含比例共用一次交集计算，阈值为零时仍要求实际相交。无效选项回退到默认值，原始检测记录不被修改。

PDF 手势缩放累计原始滚轮位移，按阈值换算步数，每个动画帧最多执行 32 步；极端输入超出部分舍弃，未达到一步的位移保留。reset/dispose 同时取消待处理帧与当前批次；WebKit 手势只用有效的正有限缩放值更新基线。

## 双链路径的跨平台边界

Rust 双链解析先统一路径分隔符，再决定知识库相对或来源文件相对的解析方式。路径归一化保留所有不能抵消的父级 `..`；越出知识库的目标直接返回 Missing，不进入短名或别名候选。Windows 分隔符在其他桌面系统上使用相同规则。正常目标保留精确路径、忽略大小写路径、后缀、短名与别名的既有优先级，歧义仍显式返回。

目录筛选在进入文献列表循环前归一化筛选路径并生成目录前缀，每一行只处理自身路径。批量与单条匹配保持相同规则：大小写与分隔符兼容、完整目录边界比较、非 papers 目录显示完整文献库。

## 文献发现页面的通信与代理

`src/lib/plaza/frame-protocol.ts` 先校验当前 iframe 的窗口身份和来源，再接受单个、类型完整的导航、外链或入库动作。入库请求和回执使用请求 ID 关联；仅当前父窗口的有效回执可更新对应按钮。Cool Papers 页面适配器位于独立的 `bridge.js`，观察列表整体替换，按钮文案跟随应用语言。ModelScope 入库协议同步使用请求 ID。

原生 `discovery/proxy/transport.rs` 保留匿名访问，只传内容协商头；请求限制为 2 MiB，响应限制为 32 MiB，单次请求超时 30 秒。同来源重定向最多 5 次，不能切换协议、主机或端口。跨来源资源使用其公开 URL；若上游改变为跨来源重定向，嵌入请求会失败，需要重新核对站点策略。规则不放宽现有 iframe 沙箱或原生权限。

`document.rs` 按 HTML 标签与属性处理内部链接、窗口目标和桥接注入，保留正文、注释与脚本字面量；XHR 片段与非 HTML 响应不注入脚本。外部网页结构仍由上游控制，离线页面验证不能代替线上接口兼容性验证。
